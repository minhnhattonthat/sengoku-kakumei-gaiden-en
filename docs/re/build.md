# Build pipeline (phase 3 identity build)

`python -X utf8 build.py identity` unpacks every string and LZ77 block, repacks with no edits and requires a
byte-identical ROM (sha1 6c2a4644…). `tests/test_identity.py` runs the same check plus the writers' tests on every
commit. **verified**.

## Text
- **Sites**: `data/text_sites.tsv`, 1152 aligned u32 pointers `0x08000000|target`, generated by `tools/textmap.py`
  (`--check` compares with a fresh scan; a test does too). Sites are taken only from code/literal pools
  (0x000000-0x04C3F4) and the event/script tables (0x7303B8-0x759177), targets only inside the 8 text ranges of
  `text.md` (`tools/textbank.py RANGES`). Every target starts a string (the byte before is 0, or it is the range
  start: 0x04FDF0 follows a code-pointer table). Rejected as coincidences: 10 values in sound data
  (0x4381D8-0x55EC34) that happen to equal text addresses. The build never scans the ROM for pointers.
- **Strings**: 1101 targets, 37.3 KB. Several sites can share one target (e.g. 0x07EB24 `|nやってみよ！|n` has 9).
  The euc_pointed.tsv of phase 1 missed ~100 targets (127 sites): strings starting with `|n`/`%n`, ASCII `%d` labels, and the
  debug menu's half-width katakana (0x04E018.., JIS X 0201 bytes, pointed from the 0xA000 pool).
- **Room in place** = the string, its NUL and the zero padding up to the next 4-byte boundary, never past the next
  pointed string. Unpointed bytes in the gaps (debug labels such as `ﾊｲ`/`ｲｲｴ`, padding) are never written.
- **Longer text** moves to free space 0x759178-0x7FFFFF (4-aligned, identical strings shared), every site is
  rewritten and the old slot is zero-filled. Test: every one of the 1101 strings force-moved still reads the same
  through every site.
- **Table**: `tbl/jp.tbl` from `tools/gen_jptbl.py` (EUC-JP JIS X 0208 pairs, ASCII, `00={end}`); decode -> encode is
  exact for all 1101 strings (19 keep `[XX]` escapes: half-width debug text).

## LZ77
- `data/lz_blocks.tsv` (615 blocks); `tools/lz77.py` decode/encode. Unedited blocks are kept as is; an edited block
  is recompressed in its own slot (relocation not written yet: phase 8 if a redraw outgrows its slot).

## Write checks
`build.py` refuses any write outside a text range, a listed site, an LZ block's slot or free space, then runs
`romdiff.check` on the write log (`build/writes.log`: offset, original bytes, new bytes, writer).
