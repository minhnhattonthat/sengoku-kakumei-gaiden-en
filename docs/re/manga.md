# Manga-bubble variant (D16): scroll text upright, centred lines

Found and built 2026-11-17. Tools: `tools/manga.py` (font, wrap, slices, encoder), `tools/manga_engine.py` (Thumb
patch, assembled code in `data/manga_code.hex`, regenerated by `--write`), `build.py manga` -> `build/sengoku_manga.gba`. Test: `tests/test_manga.py`.

## The reader, as the variant uses it (verified by disassembly, then in game: `work/qa/manga1..4`)
- `0x08011DDC(mode r0, x r1, y r2, string r3, varargs on the stack)` draws a whole string in one call, one OBJ slot
  per glyph. Its frame: `[sp+0x4c]` mode, `[sp+0x50]` start x, `[sp+0x54]` start y, `[sp+0x58]` next slot,
  `[sp+0x5c]` vararg pointer; r6 = x, r7 = y, sb = string pointer.
- **Mode 0 = the pink scroll only**: one caller, 0x08012D14 (x 0x1C, y 4). Slots 0x3C-0x5F (36), drawn hidden
  (record +0x12 = 0) and revealed by 0x080124D8, one slot per `[0x030019B5]` frames (0 = all at once; setter
  0x08012634), capped at 0x24 = 36. Mode 1 (visible at once, slots from `[0x030019AC]`, <= 0x3B): the name box
  (0x0801145C, x 0xC1), the link lobby names (0x08013CDE/0x08013D08, table 0x08733888), the results labels
  (0x08039E6E.., strings 0x08202114 / table 0x087469B0).
- Slot record (24 bytes at `[0x030019A8] + 24*slot`) starts with the OAM attributes: +0 y (byte), +2 attr1 (x in
  bits 0-8), +4 attr2; 0x080477FC writes them.
- Position advance 0x08011DB8 (9 callers, all in the reader): y += 12, wrap to the next column (x -= 12) past
  y 159. `|n` (0x0801225C): x -= 12, y = start y (ignored at the top of an auto-wrapped column).
- `%n` is **case 'n' at 0x08012130**, not the `%s` case 0x08011F38: the name is `[0x030019B8]` -> u16 entries
  (name-grid index + 1), code = u32 at 0x08733660 + 4*(index-1); the slot is counted *before* the advance and
  r5 still points at the letter's entry.
- Glyph draw 0x08011C80 -> 0x080115EC renders the entry's u16 rows into a 16x16 OBJ: all 16 px of a row show.

## The patch (`tools/manga_engine.py`)
- Font table: the engine's copy at 0x7E0100 (990 originals + v1 pairs for the results labels + manga slices);
  **entry +4** (u16, always 0 in the original) = the glyph's advance in mode 0 (0 = 12). Slice codes b0 0x01-0x24,
  b1 0x01-0xFF; lookup 0x7E0000 maps them to `[0x7FFFF0] + (b0-1)*255 + (b1-1)`.
- Handlers at 0x7FF800 (branch table: +0 advance, +2 newline, +4 end), hooks:
  - 0x08011DB8 (12 bytes: `push {r4,lr}; ldr r4,=adv; bx r4`): mode 0 -> x += advance of the glyph just drawn
    (code at `[sb-2]`, or the name letter's code; a name letter's sprite is pulled left 4 px, since its glyph sits
    centred in a 12 px column for mode 1). Mode 1 -> the original code.
  - 0x0801225C (`|n`, 8 bytes): mode 0 -> centre the finished line (every slot of this call whose y byte is the
    line's y moves so the line's centre is x 22), then x = start x, y += 11.
  - 0x08012450 (end of string, 8 bytes): mode 0 -> centre the last line, then move all the call's slots so the
    block's centre is y 80 (scroll inside x 2-41, y 2-157).
- Reveal order = slot order = reading order, so the typewriter shows lines left to right, top to bottom.

## Layout (`tools/manga.py`)
- Condensed caps 3x7 (I 1 px, N 4, M/W 5), advance = width + 1, space 3; lowercase only for player names.
- A page's English is one paragraph (v1's `|n` were 24-letter rotated lines); wrap to 38 px; a word too wide
  breaks after its own hyphen (TOYOTOMI-/DONO), else at a syllable (HYPHENATION table, then V-CV / VC-CV).
- `%n` reserves 8 letters x 4 px (the name box holds 8).
- Limits checked for every page at build time: <= 13 lines, <= 36 slots (a name counts 8). Real script: <= 11
  lines, <= 24 slots, 2385 distinct slices.

## Not changed (v1 style)
- Results labels (mode 1, one 12 px column): v1 rotated pairs.
- OBJ label graphics (`gfx/bank*.tsv`), BG menus, name-entry grid, ending cards, title: v1 rotated drawings.
